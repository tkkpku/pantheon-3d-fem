# 入门第 3 课 · 2000 行脚本的噩梦：怎样不把代码写成灾难

> 写给：写过「一个文件从头写到尾」的脚本的学生。
> 承诺：读完这篇，你能一眼看出任何项目代码的「工程质量」，并写出三个月后自己还看得懂的代码。
> 前置：会一点 Python（会 if/def/import 就够）。

---

## 先给一张地图

代码有两种死法：**跑不起来**（bug），和**没人敢改**（灾难）。新手怕第一种，老手怕第二种。

「没人敢改」长什么样：一个 2000 行的文件，变量叫 `a1、a2、temp、data2`，关键数字 `22.03、5.9` 散落在第 47 行和第 890 行，想改一个参数要全文搜索五处。**三个月后连作者自己都不敢动它。**

本课讲万神殿项目怎么躲开第二种死法——四条规矩，全部来自 16 个源文件的真实写法。

---

## 第 1 节 规矩一：参数只住一个家（唯一参数源）

万神殿穹顶的内半径 22.03 米，这个数字在项目里出现**过几百次**——但写在文件里的只有一处：`config/params.py`。

```python
# config/params.py —— 全项目唯一参数源
R_INNER = 22.03   # 内表面球面半径 (m) ✅ 激光扫描+摄影测量双验证
T_OCULUS = 1.5    # Oculus 边缘厚度 (m) ✅ Masi 2018 p.5
```

任何其他文件要用这个数，只能：

```python
from config.params import R_INNER   # 引入，不重写
```

**为什么**：如果 22.03 写在了 8 个文件里，哪天文献说其实是 22.05——你要改 8 处，漏一处就是一处隐蔽 bug（其他文件都在算「另一座穹顶」）。而唯一参数源只改一处，全部生效。

**每个参数还带「户口」**：✅（双源验证过）/ ⚠️（待核对）/ 🔴（占位值，查不到就坦白标着）。**「不编造参数」从口号变成文件结构**——这个设计是万神殿项目最值得抄的一条。

▢ **你试试 1**：打开 `config/params.py`，找出三个带 ✅ 的参数和两个带 🔴 的参数，读它们的注释。感受「每个数字都有来历」是什么体验。

⚠️ **新手常犯**：图省事把数字直接写进公式（「魔法数字」）。**判据：数字出现在代码里时，旁边没有名字和单位，就是魔法数字。**

## 第 2 节 规矩二：一个函数只做一件事

万神殿几何脚本 `minimal_dome_demo.py` 的函数分工：

```python
def create_shell():     # 只负责：造等厚球壳
def truncate_dome():    # 只负责：切成半球
def cut_oculus():       # 只负责：切出天窗洞
def mark_groups():      # 只负责：贴物理组标签
def main():             # 只负责：按顺序调度上面四步 + 撒网导出
```

每个函数一段话能说完职责；`main` 读起来像菜谱：

```python
shell = create_shell()        # [1/4] 造壳
shell = truncate_dome(shell)  # [1.5/4] 切半球
shell = cut_oculus(shell)     # [2/4] 切天窗
mark_groups(shell)            # [3/4] 贴标签
```

**「一函数一职责」的验收标准**：你能不能用一句话说出这个函数干什么？说不出 → 拆。

▢ **你试试 2**：找你写过的最长的一个函数，试着把它拆成两个，各写一句话职责。拆不动也没关系——**「想拆但拆不动」本身就是诊断结果**（职责缠在一起了）。

⚠️ **新手常犯**：函数名 `func1`、`process`、`do_stuff`。**函数名是写给读者的第一个信号**——`cut_oculus` 一眼就知道在切天窗。

## 第 3 节 规矩三：报错要在源头喊，别在终点哭（fail fast）

万神殿的求解器开头必有这一段：

```python
base_facets = facet_tags.find(400)     # 找「拱脚面」的标签
if base_facets.size == 0:
    raise RuntimeError("find(400) 为空：物理组没贴好，回 geometry/minimal_dome_demo.py 检查")
```

**如果删掉这三行会怎样？** 程序会在几小时后、几十万行计算的中途，报一个完全看不懂的错（比如矩阵奇异）——那时你已经忘了问题出在「标签没贴上」。

**fail fast 的哲学**：**错误越早被发现，代价越小。** 发现错误的那一刻，把「什么错了 + 去哪修」喊出来，比让它潜伏到终点变成怪错强一万倍。

▢ **你试试 3**：在你的代码里找一个「没有检查就直接用」的地方（比如打开一个可能不存在的文件），加上两行检查：不存在就 raise，报错信息里写清去哪找这个文件。

## 第 4 节 规矩四：文件名就是说明书（命名即元数据）

万神殿的求解结果文件长这样：

```
c4_ml_swpsh_E1.0_sh6.00e-05_sigma.bp
```

不需要打开文件，只看名字就知道：**C4 算例、2 米网格+分层密度、自重加干缩荷载、弹模 1.0 GPa、干缩应变 6e-5、这是应力场。**

命名规则的威力在「搜索」：想找「所有自重+干缩、弹模 1.0 的结果」，一条 `glob("*swpsh*E1.0*")` 全出来。**起名时问自己：三年后的人只看文件名，能还原出什么信息？** 还原得出来 = 好名字。

▢ **你试试 4**：把你电脑里名字最糟糕的一个文件（`新建文件夹(3).docx` 之类的），按「内容+日期+版本」重新命名。从此养成习惯。

## 第 7 节 模块化实战：万神殿的目录即设计

第 1~6 节讲了四条规矩。这一节看它们如何长成「目录结构」（总纲 §3 的规划 vs 实际演进）：

```
config/params.py        → 唯一参数源（规矩一的家）
geometry/*.py           → 捏泥巴（每脚本一个算例）
fem_solver/*.py         → 求解（每脚本一个物理）
tools/*.py              → 工具（Richardson/验证/诊断）
verification/env_check.py → 自检（环境体检）
docs/                   → 文档（中继/日志/教程/成书）
output/                 → 产物（不入库）
```

**目录即设计的三个原则**：
1. **按职责分层**：参数/几何/求解/工具/文档——**每个目录一个动词**；
2. **数据流清晰**：params → geometry → fem_solver → output（一条流水线，目录顺序就是数据流顺序）；
3. **产物隔离**：output 不入 git（第 2 课判据）——**「能再生的」与「是资产的」分家**。

**sys.path 引导四行**（全项目每个脚本的开头，P-04 教训的遗产）：

```python
import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).resolve().parent.parent))
from config.params import R_INNER, ...
```

**为什么必须有**：任何目录下跑脚本都能找到 config——**「模块化项目的第一行代码是路径引导」**。漏了它 = ModuleNotFoundError（老教材 8/13 纠错 #4 的根）。

▢ **你试试 5**：画一张万神殿的数据流图：params 的哪个参数流向 geometry 的哪个函数、最终变成 output 的哪个文件。**画得出 = 目录结构内化。**

## 第 8 节 调试技巧：print 之外的三件武器

四条规矩防 bug，真出了 bug 怎么查？**三件武器**（万神殿实战用过的全部）：

**武器一：fail fast 的报错信息**（第 3 节规矩三的调试面）——报错要带「什么错了 + 去哪修」。写报错信息时想：**三个月后的自己看到这行，能不能直接去修？**

**武器二：分步打印 + [x/y] 进度**（geometry 脚本的惯例）——`[1/4] 造壳... [2/4] 切天窗...`——**卡住的那一步立刻现形**。长流程没有进度打印 = 盲跑。

**武器三：最小复现**（科学方法在调试里的应用）——**把 bug 隔离到最小脚本**：`_diagnose_fillet.py`（46 行）就是典范——**不修大项目，先在一个盒子上复现 fillet 报错**。**「最小复现」三步**：删无关代码 → 保留触发 bug 的最短路径 → 在最小脚本上修。

**调试的元心法**：**「先复现，再修」**——复现不出来的 bug 修不好（修了也无法验证）。万神殿 P-02 的判决书、P-09 的诊断脚本，全是「先复现」的产物。

▢ **你试试 6**：找你自己最近的一个 bug，用「最小复现」三步把它隔离成 20 行以内的脚本。**做得到 = 调试能力过关。**

⚠️ **新手常犯**：一出 bug 就到处 print 乱试——**没有假设的调试是抽奖**。先提假设（「我猜是单位错了」），再设计验证（打印一个已知量），**假设-验证循环才是调试**。
