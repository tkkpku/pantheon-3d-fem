## 1. 前置理解：为什么一个简单的 FEM 脚本不够用？

### 1.1 单脚本方案的灾难

假设你把整个项目写在一个 `main.py` 里：

```python
# main.py —— 2000 行代码
# 前 500 行：定义几何参数
R_SPHERE = 22.03
T_BASE = 5.90
# ... 几十个参数

# 中间 500 行：Gmsh 几何建模
import gmsh
gmsh.initialize()
# ... 几百行建模代码

# 中间 500 行：FEniCSx 求解
import dolfinx
# ... 几百行 FEM 代码

# 最后 500 行：PyVista 可视化
import pyvista as pv
# ... 几百行绑图代码
```

**三个月后，你想换一个边界条件试试。** 你需要在 2000 行代码里找到「边界条件定义」的那几行——它们可能分散在第 650、890、1230 行。你改了一个地方，忘了改另一处。程序报错，你不知道是哪一步出的问题。你想用 C1（纯穹顶）的结果对比 C2（穹顶+鼓座），但你发现代码里的几何是硬编码的——要跑 C1 你得注释掉鼓座相关代码，跑 C2 又得取消注释。

**这种代码叫「意大利面条代码（Spaghetti Code）」。**

### 1.2 模块化工程的好处

```
pantheon-3d-fem/
├── config/params.py          # 参数改这里 → 全项目生效
├── geometry/dome_geometry.py # 穹顶几何 → 只管穹顶
├── geometry/drum_geometry.py # 鼓座几何 → 只管鼓座
├── fem_solver/solve_linear.py # 线弹性求解 → 只管求解
├── post_process/plot_3d.py   # 三维云图 → 只管绑图
└── cases/case_C1_dome_only.py # C1 算例 → 组合上面的模块
```

**好处**：
- **改参数** → 只改 `params.py` 一个文件
- **换几何** → 只改 `geometry/` 里的文件，求解器不受影响
- **换求解器设置** → 只改 `fem_solver/` 里的文件，几何不受影响
- **跑不同算例** → 每个 `case_*.py` 是一个独立的「配方」，组合不同模块
- **新人看懂** → 从 `config/` → `geometry/` → `fem_solver/` → `cases/` 顺着读下来就是完整的项目逻辑

### 1.3 本项目的模块化哲学

> **每个 `.py` 文件只做一件事，而且把这件事做好。**

- `dome_geometry.py` 只负责「在 Gmsh 中创建穹顶几何」
- `mesh_generate.py` 只负责「对已建好的几何划分网格」
- `solve_linear.py` 只负责「接收网格 + 参数 → 求解 → 返回位移和应力」
- `plot_3d.py` 只负责「接收结果数据 → 画云图」

这些模块各司其职，通过明确的输入输出接口互相调用。像搭积木一样——每一块积木都可以独立测试，组合起来就是整个项目。

## 3. 参数统一管理：`config/params.py`

### 3.1 为什么需要「唯一参数源」

这是模块化工程中**最重要的一条规则**：

> **任何数值参数都不能硬编码在功能代码里。所有参数必须从 `config/params.py` 导入。**

违反这条规则的后果：
- 同一个参数（如 `R_SPHERE = 22.03`）出现在 5 个不同文件中
- 你想改成 `R_SPHERE = 22.00` 做敏感性分析 → 漏改了 2 个文件 → 结果矛盾 → 排查半天
- 三个月后你完全不知道 `22.03` 这个数是从哪来的

### 3.2 `config/params.py` 结构设计

```python
"""
万神殿穹顶三维FEM重构 · 全局参数配置
=====================================
这是项目的【唯一参数源】。所有模块必须从本文件导入参数，
禁止在任何其他文件中硬编码数值。

数据来源：
  - Aliberti & Alonso-Rodríguez (2017)：几何参数
  - Masi, Stefanou & Vannucci (2018)：材料参数
  - Mark & Hutchinson (1986)：定性对照

修改规则：
  - 任何参数修改必须在此文件中同步更新
  - 写明修改日期和原因（Git commit 来追踪）
"""

import numpy as np

# ============================================================
# 一、几何参数
# 来源：Aliberti & Alonso-Rodríguez (2017), Survey Model
# ============================================================

class GeometryParams:
    """穹顶几何参数"""

    # --- 整体尺寸 ---
    R_INNER = 22.03          # 内表面球面半径 [m]
    R_OUTER = None           # 外表面球面半径 = R_INNER + t （由变厚度函数确定）

    T_BASE = 5.90            # 拱脚厚度 [m]
    T_OCULUS = 1.50          # Oculus 处厚度 [m]
    D_OCULUS = 8.95          # Oculus 直径 [m]

    # --- 球心位置 ---
    SPHERE_CENTER_OFFSET = 0.37  # 球心在檐口线后的距离 [m]

    # --- 藻井参数 ---
    N_COFFER_LEVELS = 5      # 藻井层数
    N_SECTORS = 28           # 每层扇区数（28等分圆周）

    # --- 藻井尺寸（Aliberti 2017 Table 2，自下而上 Level 1→5）---
    COFFER_WIDTH_BOTTOM = [3.88, 3.74, 3.39, 2.92, 2.38]  # 底宽 [m]
    COFFER_WIDTH_TOP = [3.77, 3.48, 3.02, 2.50, 2.02]     # 顶宽 [m]
    COFFER_HEIGHT = [4.08, 3.79, 3.52, 3.05, 2.39]       # 高度 [m]

    # --- 藻井深度（Aliberti 2017 Table 3，最深处~0.23m）---
    COFFER_MAX_DEPTH = 0.23    # 藻井最大深度 [m]

    # --- 鼓座（待补充）---
    DRUM_HEIGHT = None         # ⚠️ 待从文献中提取
    DRUM_THICKNESS = None      # ⚠️ 待从文献中提取

    @classmethod
    def thickness_at(cls, phi):
        """
        穹顶厚度随子午角 φ 的变化（线性变厚度）
        φ = 0° 对应 Oculus，φ = 90° 对应拱脚

        Args:
            phi: 子午角 [弧度]，从 Z 轴（球顶）起算

        Returns:
            t: 该处的厚度 [m]
        """
        phi_oculus = np.arcsin(cls.D_OCULUS / (2 * cls.R_INNER))
        t = cls.T_OCULUS + (cls.T_BASE - cls.T_OCULUS) * (phi - phi_oculus) / (np.pi/2 - phi_oculus)
        return np.clip(t, cls.T_OCULUS, cls.T_BASE)


# ============================================================
# 二、材料参数
# 来源：Masi, Stefanou & Vannucci (2018)
# ============================================================

class MaterialParams:
    """古罗马混凝土力学属性"""

    E = 14.8e9               # 弹性模量 [Pa] = 14.8 GPa
    NU = 0.2                 # 泊松比 [-]
    F_T = 0.08e6             # 抗拉强度 [Pa] = 0.08 MPa
    # F_C = None             # 抗压强度（线弹性分析暂不需要）

    # --- 密度梯度（分段线性）---
    # Masi et al. (2018)：从顶部轻质浮石 → 底部致密玄武岩
    @staticmethod
    def density_at(phi):
        """
        密度随子午角 φ 变化

        Args:
            phi: 子午角 [弧度]，从 Z 轴（球顶）起算

        Returns:
            rho: 密度 [kg/m³]
        """
        phi_deg = np.degrees(phi)

        if phi_deg <= 12:
            return 1350.0      # 顶部：轻质浮石
        elif phi_deg <= 25:
            return 1650.0      # 过渡区：混合骨料
        elif phi_deg <= 40:
            return 1900.0      # 中下部：较重骨料
        else:
            return 2100.0      # 底部：致密玄武岩


# ============================================================
# 三、荷载参数
# ============================================================

class LoadParams:
    """荷载参数"""

    G = 9.81                  # 重力加速度 [m/s²]
    # SHRINKAGE_EQUIVALENT_STRESS = 182e3  # ⚠️ V1.0 反算值，V2.0需重新标定 [Pa]
    # SHRINKAGE_STRAIN = 1.23e-5           # ⚠️ 等效干缩应变（仅供参考）


# ============================================================
# 四、求解器参数
# ============================================================

class SolverParams:
    """FEM 求解器配置"""

    MESH_SIZE_GLOBAL = 0.5    # 全局网格尺寸 [m]（初始值，后续做收敛性测试）
    MESH_SIZE_LOCAL_COFFER = 0.15   # 藻井凹角局部加密尺寸 [m]
    MESH_SIZE_LOCAL_INTERFACE = 0.2 # 交界面局部加密尺寸 [m]

    ELEMENT_ORDER = 2         # 单元阶次（2 = 二阶四面体）
    SOLVER_TYPE = "mumps"     # 线性求解器类型（MUMPS = 直接求解器）
```

## 4. 模块导入规范

### 4.1 绝对导入 vs 相对导入

对于一个目录结构如下的项目：

```
pantheon-3d-fem/
├── config/
│   └── params.py
├── geometry/
│   └── dome_geometry.py
└── cases/
    └── case_C1_dome_only.py
```

**绝对导入**（从项目根目录开始的完整路径）：

```python
# 在 cases/case_C1_dome_only.py 中
from config.params import GeometryParams, MaterialParams
from geometry.dome_geometry import build_dome_geometry
from geometry.mesh_generate import generate_mesh
```

**相对导入**（使用 `.` 表示当前包）：

```python
# 在 geometry/assemble_model.py 中导入同目录的 dome_geometry
from .dome_geometry import build_dome_geometry
from .drum_geometry import build_drum_geometry
```

### 4.2 本项目推荐导入方式

| 场景 | 推荐方式 | 示例 |
|---|---|---|
| `cases/*.py` 导入任何模块 | **绝对导入** | `from geometry.dome_geometry import build_dome_geometry` |
| `geometry/` 内部互相导入 | **相对导入** | `from .dome_geometry import build_dome_geometry` |
| `fem_solver/` 内部互相导入 | **相对导入** | `from .mesh_io import read_mesh` |
| `post_process/` 导入 `fem_solver/` | **绝对导入** | `from fem_solver.solve_linear import solve_linear_elastic` |

> **核心原则**：`cases/` 里的脚本是「顶层调用者」，用绝对导入。包内部（`geometry/`、`fem_solver/` 等）互相调用用相对导入，这样整个包作为一个整体可以被移动或重命名。

### 4.3 `__init__.py` 的作用

`__init__.py` 有三个作用：
1. **让 Python 把这个文件夹当作「包」**（可以 `import geometry`）
2. **控制 `from package import *` 的行为**（通过 `__all__` 变量）
3. **在包被导入时执行初始化代码**

本项目的 `__init__.py` 示例：

```python
# geometry/__init__.py
"""
geometry 包：万神殿穹顶三维参数化几何建模与网格划分
"""

# 控制 from geometry import * 暴露哪些接口
__all__ = [
    "build_dome_geometry",
    "build_drum_geometry",
    "assemble_full_model",
    "generate_mesh",
]

from .dome_geometry import build_dome_geometry
from .drum_geometry import build_drum_geometry
from .assemble_model import assemble_full_model
from .mesh_generate import generate_mesh
```

这样，外部调用者可以简洁地：
```python
from geometry import build_dome_geometry, generate_mesh
```

### 4.4 运行时路径问题

当你在 `cases/` 目录下运行 `python3 case_C1_dome_only.py` 时，Python 需要能找到 `config`、`geometry` 等包。有两种方式：

**方式一**：始终从项目根目录运行（推荐）
```bash
cd /mnt/c/Users/tan83/Desktop/pantheon-3d-fem
python3 cases/case_C1_dome_only.py
```

此时 Python 会自动把当前目录加入搜索路径，能正常导入。

**方式二**：在脚本开头添加路径
```python
# case_C1_dome_only.py 开头
import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).parent.parent))
```

> ⚠️ 不要硬编码绝对路径如 `sys.path.insert(0, "C:/Users/tan83/...")`——换一台电脑就全坏了。

## 5. 函数封装原则

### 5.1 一个函数只做一件事

```python
# ❌ 坏代码：一个函数做了三件事（建模 + 网格 + 求解）
def run_dome_analysis():
    # 200 行：Gmsh 建模
    gmsh.initialize()
    # ...
    # 100 行：画网格
    # ...
    # 150 行：FEniCSx 求解
    # ...

# ✅ 好代码：拆成三个独立的函数
def build_dome_geometry(params):
    """只在 Gmsh 中创建穹顶几何"""
    pass

def generate_mesh(params):
    """只划分网格并导出"""
    pass

def solve_elastic(mesh_file, params):
    """只做 FEM 求解"""
    pass
```

### 5.2 输入输出类型标注（Type Hints）

Type hints 不会影响代码运行，但会让你和 IDE 在三个月后一眼看懂函数要什么、返回什么：

```python
import numpy as np
from typing import Tuple, Optional, List
```

### 6.2 变量与函数命名

| 类型 | 规范 | 示例 |
|---|---|---|
| 函数名 | `snake_case` + 动词开头 | `build_dome_geometry()`, `compute_principal_stresses()`, `export_to_csv()` |

### 6.3 类命名

| 类型 | 规范 | 示例 |
|---|---|---|
| 类名 | `PascalCase`（每个单词首字母大写） | `GeometryParams`, `MaterialParams`, `SolverParams`, `StressTensor` |

| 类型 | 规范 | 示例 |
|---|---|---|

### 6.5 命名时的额外注意

- **不要用拼音**。`qiongding.py` ❌ → `dome_geometry.py` ✅

- **物理量用标准符号**。`sigma_theta_theta` ✅，`circumferential_stress` 也可以，但 `s_tt` 就不太行。
- **不要用 Python 关键字或内置函数名**。`list`、`dict`、`type`、`id` 不能做变量名。

```python
"""
穹顶参数化几何建模
==================
在 Gmsh 中创建万神殿穹顶的三维几何体。

功能：
  - 球面壳体的参数化构建
  - 变厚度定义（Oculus 1.50m → 拱脚 5.90m）
  - 五层阶梯藻井的布尔挖除
  - 物理组标记（区分穹顶体、内表面、外表面、拱脚面）

数据来源：
  - Aliberti & Alonso-Rodríguez (2017)：球面半径、藻井尺寸
  - Mark & Hutchinson (1986)：厚度参数

使用方式：
  >>> from geometry.dome_geometry import build_dome_geometry
  >>> gmsh.initialize()
  >>> dome_volume_tag, surface_tags = build_dome_geometry()
  >>> gmsh.model.occ.synchronize()
"""

import numpy as np
from typing import Tuple, Dict, List
from config.params import GeometryParams as GP


def build_dome_sphere() -> int:
    """创建穹顶的内外球面壳（尚未挖藻井）。

    坐标系：原点在球心，Z 轴向上指向 Oculus。

    Returns:
        dome_volume: Gmsh 中穹顶体的 tag
    """
    import gmsh

    # 外球面半径 = 内径 + 厚度
    r_outer = GP.R_INNER + GP.T_BASE

    # 计算 Oculus 对应的子午角（从球顶起算）
    phi_oculus = np.arcsin(GP.D_OCULUS / (2 * GP.R_INNER))

    # 穹顶角度范围：从 Oculus 到拱脚（φ = π/2）
    angle_range = np.pi/2 - phi_oculus

    # 创建外球面（完整球，后续裁剪）
    outer_sphere = gmsh.model.occ.addSphere(0, 0, 0, r_outer)
    # 创建内球面
    inner_sphere = gmsh.model.occ.addSphere(0, 0, 0, GP.R_INNER)

    # 布尔减法：外球 - 内球 = 球壳
    dome_shell = gmsh.model.occ.cut([(3, outer_sphere)], [(3, inner_sphere)])

    # 返回球壳体的 tag
    return dome_shell[0][0][1]   # Gmsh 的 cut 返回格式比较复杂


def build_coffer_cutout(
    level: int,        # 藻井层号 (0-4，从底部起算)
    sector: int,       # 扇区号 (0-27)
) -> int:
    """创建单个藻井的挖除几何体（用于布尔减法）。

    藻井是嵌在球壳内表面上的倒梯形凹槽，由四个内部面和一个外底面组成。

    Args:
        level: 藻井层级，0 = 最底层（靠近拱脚），4 = 最顶层（靠近 Oculus）
        sector: 扇区编号，0-27，顺时针排列

    Returns:
        coffer_solid: Gmsh 中藻井挖除体的 tag
    """
    import gmsh

    # 获取该层藻井的尺寸
    width_bottom = GP.COFFER_WIDTH_BOTTOM[level]
    width_top = GP.COFFER_WIDTH_TOP[level]
    height = GP.COFFER_HEIGHT[level]
    depth = GP.COFFER_MAX_DEPTH

    # 计算该藻井在球面上的位置
    # （这里展示框架，具体实现需要球面坐标转换）
    phi_center = _compute_coffer_center_phi(level)
    theta_center = sector * (2 * np.pi / GP.N_SECTORS)

    # 创建藻井的挖除几何体（简化展示）
    # 实际实现需要用布尔运算构建梯形棱柱
    coffer_box = gmsh.model.occ.addBox(
        x=0, y=0, z=0,      # 临时位置，后续需要旋转到球面上
        dx=width_bottom,
        dy=depth,
        dz=height,
    )

    # TODO: 将 box 旋转/平移到球面上的正确位置
    # TODO: 应用球面曲率（对于精确建模，藻井底面应贴合球面）

    return coffer_box


def _compute_coffer_center_phi(level: int) -> float:
    """计算指定层藻井中心对应的子午角。

    Args:
        level: 藻井层级（0-4，从底部起算）

    Returns:
        phi: 子午角 [弧度]
    """
    # 五层藻井分布在从拱脚（φ=90°）到某高度之间
    # 各层中心的粗略位置（需要根据实测数据精确校准）
    phi_levels = np.radians([75, 60, 45, 30, 18])
    return phi_levels[level]


def build_dome_geometry() -> Dict[str, int]:
    """构建完整的穹顶几何（含藻井挖除）。

    这是本模块的主入口函数。调用它即可在 Gmsh 中创建完整的穹顶模型。

    Returns:
        tags: 字典，包含各物理组的 Gmsh tag：
            - "dome": 穹顶体的 tag
            - "inner_surface": 内表面的 tag
            - "outer_surface": 外表面的 tag
            - "base_surface": 拱脚面（与鼓座连接面）的 tag
            - "oculus_edge": Oculus 边缘的 tag
    """
    import gmsh

    # 1. 创建球壳
    dome_tag = build_dome_sphere()
    gmsh.model.occ.synchronize()

    # 2. 逐层逐扇区挖除藻井
    coffer_tags = []
    for level in range(GP.N_COFFER_LEVELS):
        for sector in range(GP.N_SECTORS):
            coffer_tag = build_coffer_cutout(level, sector)
            coffer_tags.append(coffer_tag)

    gmsh.model.occ.synchronize()

    # 3. 布尔减法：球壳 - 所有藻井
    # （完整实现需要处理 Gmsh 的布尔操作语法）
    # dome_with_coffers = gmsh.model.occ.cut(...)

    # 4. 标记物理组
    # （完整实现需要遍历面和体，根据几何位置或法向分类）

    # 5. 返回物理组 tags
    tags = {
        "dome": dome_tag,
        # "inner_surface": ...,
        # "outer_surface": ...,
        # "base_surface": ...,
        # "oculus_edge": ...,
    }

    return tags
```
