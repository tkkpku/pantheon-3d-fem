## 第 1 章 环境总览：你的开发环境长什么样

### 1.1 一张图看懂三层结构

```text
Windows 11（宿主）
  ├── 文件系统：C:\Users\tan83\Desktop\codex\pantheon-3d-fem（项目）
  └── WSL2 Ubuntu 22.04（虚拟机）
        └── Miniconda
              └── pantheon-fem 环境（Python 3.11 + FEM 全家桶）
                    ├── gmsh 4.15.2（几何+网格）
                    ├── dolfinx 0.8.0（FEniCSx 求解）
                    ├── pyvista 0.48.4（可视化）
                    └── meshio / numpy / scipy / matplotlib ...
```

**关键理解**：

- 项目代码在 **Windows 文件系统**（`/mnt/c/...` 是 WSL 视角的路径）；
- 所有 Python 包装在 **WSL 内部**（不占 Windows C 盘）；
- WSL 里能直接访问 Windows 文件（路径 `/mnt/c/...`）；
- 反过来 Windows 不能直接 import WSL 的包——**所以 Python 程序都在 WSL 里跑**。

### 1.2 为什么是这套组合

| 组件 | 为什么选它 |
| --- | --- |
| WSL2 | Linux 环境跑科学计算最省心，不污染 Windows |
| Miniconda | 环境隔离，一套机器多个 Python 互不干扰 |
| conda-forge | FEniCSx 官方只支持 conda-forge 路线（PyPI 没有） |
| 清华镜像 | 国内下载速度（环境档案里的约定） |

### 1.3 常用路径对照

| 含义 | Windows 路径 | WSL 路径 |
| --- | --- | --- |
| 项目根 | `C:\Users\tan83\Desktop\codex\pantheon-3d-fem` | `/mnt/c/Users/tan83/Desktop/codex/pantheon-3d-fem` |
| conda 环境 | 在 WSL 内 | `/home/tan83/miniconda3/envs/pantheon-fem` |
| 网格输出 | `...\output\meshes` | `.../output/meshes` |

### 1.4 本章小结

1. 三层结构：Windows 文件 + WSL 系统 + conda 环境；
2. 代码在 Windows、包在 WSL，Python 在 WSL 里跑；
3. 记住两条路径写法（Windows `\` vs WSL `/`）。

### 1.5 小练习

1. 打开 WSL 终端，用 `pwd` 看当前目录；

## 第 3 章 排错手册：按图索骥

### 3.1 错误分类

先判断是三类中的哪一类：

| 类别 | 典型症状 | 方向 |
| --- | --- | --- |
| 环境类 | `ModuleNotFoundError`、命令找不到 | 第 3.2 节 |
| 路径类 | 文件找不到、路径不对 | 第 3.3 节 |
| 运行类 | 脚本报错、结果不对 | 第 3.4 节 |

### 3.2 环境类

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `ModuleNotFoundError: No module named 'gmsh'` | 环境没激活 | `conda activate pantheon-fem` |
| `conda: command not found` | conda 没初始化 | `source ~/miniconda3/etc/profile.d/conda.sh` |
| `command not found: python` | WSL 里没进交互 shell | 用 `bash -lc` 或重开终端 |
| 包版本不对 | 环境串了 | `conda env list` 确认当前环境 |

### 3.3 路径类

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `No such file or directory` | 路径写错 | 用 `pwd` 确认，`ls` 验证 |
| `/mnt/c/...` 找不到 | Windows 路径写错 | Windows 路径 → WSL：`C:\x` → `/mnt/c/x` |
| `ModuleNotFoundError: config` | 运行目录不对或缺路径引导 | 在项目根运行；文档4 第 9.2.1 节 |
| 中文路径报错 | 特殊字符 | 项目路径无中文（当前满足），别改 |

### 3.4 运行类

| 现象 | 方向 |
| --- | --- |
| 求解不收敛 | 检查 BC、单位、材料参数 |
| 网格生成慢 | 尺寸太大/FromCurvature 过激 |
| 结果量级离谱 | 单位混用（Pa/MPa/mm/m） |
| 内存不足 | 网格太细，先粗网格 |

### 3.5 终极排错口诀

```text
报错先看环境（激活没）
再看路径（目录对没）
然后看数据（单位、参数）
最后才怀疑代码逻辑
```

### 3.6 本章小结

1. 错误分三类：环境/路径/运行；
2. 环境类先 `conda activate`；
3. 路径类先 `pwd` + `ls`；
4. 运行类先查单位与参数。

## 第 5 章 · 实战增补（2026-08 万神殿战役实录）

> 本章基于《万神殿全解》成书卷七，把本项目 2026-08-10~17 实战中踩过的环境坑全部收录。与第 3 章排错手册互补：第 3 章是「按图索骥」，本章是「真实病历」。

### 5.1 环境路线史：为什么最终是 conda-forge

本项目环境路线经历了两次大改，每一次都是被现实打回来的：

| 阶段 | 路线 | 结局 |
| --- | --- | --- |
| 7/24 立项 | pip 安装（requirements.txt） | ❌ 8/11 实测：`fenics-dolfinx` 未上架 PyPI——清华/阿里/官方三源全部 404。**pip 路线死路** |
| 8/10 | WSL2 + .venv pip | ❌ 同上 |
| **8/11 D1 定稿** | **WSL2 + Miniconda + conda-forge（清华镜像）+ pip 补 gmsh** | ✅ env_check 10/10 全绿 |

**关键认知**：FEniCSx 官方只发布 conda-forge 渠道。第二个隐藏坑：**conda-forge 的 gmsh 不含 Python 绑定**，必须 `pip install gmsh` 补装。requirements.txt 因此从「安装清单」降级为「参考清单」——文档随现实演进，是诚实文档的样板。

### 5.2 清华镜像三级回退（setup_env_wsl.sh 实录）

```bash
CHANNEL="https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/conda-forge/"
curl -fL --retry 3 -o /tmp/miniconda.sh \
  "https://mirrors.tuna.tsinghua.edu.cn/anaconda/miniconda/Miniconda3-latest-Linux-x86_64.sh" \
  || curl -fL --retry 3 -o /tmp/miniconda.sh \
  "https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh"
```

三点纪律：① `--retry 3` 重试；② `||` 失败自动回退官方源；③ `set -euo pipefail` 全脚本失败即停。**幂等设计**：每步 `if [ ! -x ... ]` 判存在才执行——脚本可重复跑不炸。

### 5.3 实战坑谱（2026-08 全部实测）

| # | 坑 | 症状 | 解法 |
| --- | --- | --- | --- |
| 1 | WSL 发行版名字 | `wsl -d Ubuntu` 找不到 | 真名是 `Ubuntu-22.04`（`wsl -l -v` 查） |
| 2 | conda 命令不可用 | bashrc 缺初始化 | `conda init bash` + **重开终端**生效 |
| 3 | WSL 管道中文编码 | 输出乱码/管道中断 | `exec > log.txt 2>&1` 整链重定向（run_c1_chain.sh） |
| 4 | C 盘空间不足 | C 盘仅剩 27GB | conda 环境放 WSL 内部磁盘（剩 920GB） |
| 5 | git 沙箱 ownership | `dubious ownership` 拒读 | `git -c safe.directory="<路径>"` 单命令绕过，**不写全局 config** |
| 6 | 沙箱访问 WSL | 权限拒绝 | dsh 沙箱需 danger-full-access 权限（每次弹审批，可用但烦） |

### 5.4 DOF 内存极限实证（8/17 实测，规划算例规模的依据）

| 场景 | DOF | 结果 |
| --- | --- | --- |
| dome lc0.55 | 1.83M | ✅ 顺跑 |
| C6 全结构 lc0.75 | 2.2M | ✅ 顺跑（RSS 21.7GB/88%，CPU 104%） |
| C6 全结构 lc0.67 | ≈3.1M | ❌ OOM（96% + 8GB swap） |

**结论**：24GB 内存机器的 dolfinx 安全上限 ≈ **2.3~2.5M DOF（约 9.9KB/dof）**。规划算例前先算账：目标 DOF × 10KB < 可用内存 × 85%。「500 万 DOF」是超算级需求，本机跑不动——这是 8/31 与老师聊 HPC 的实证论据。

### 5.5 环境自检哲学：装完即验，不是装完即用

`env_check.py` 的 10 项检查设计三原则：① `__import__` 动态导入（一个失败不连坐）；② `getattr(mod, "__version__", "未知")` 优雅处理无版本号包；③ 退出码 0/1 机器可判。**任何环境脚本的最后一步都应该是自检**——「全绿」二字才是装环境的完成标志。
